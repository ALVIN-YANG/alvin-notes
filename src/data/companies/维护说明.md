# AI 公司观察维护

当前公司档案在 `catalog.json`，已核实动态在 `updates.json`，来源检查状态与待核实线索在 `monitor.json`。退出观察的公司及历史动态保存在 `archive.json`，旧档案链接保留，但不出现在目录或周同步中。公司目录为 `/companies/`，档案使用稳定 ID。公司被收购、上市或关闭后更新状态并保留档案。

每周一北京时间 08:30，仓库的 `.github/workflows/ai-companies.yml` 在 GitHub Actions 检查已登记的官方页面，保存正文摘要哈希、实际检查日期和失败原因，并提交检查状态。不依赖本机开机或当前会话，没有每日检查，也没有本地或会话定时任务。

当前 Action 只自动监测来源变化，尚未自动更新公司档案、生成本期动态或复核商业分析。待核实线索需核对正文及事件日期后维护；不能将抓取成功、正文哈希变化或状态提交宣称为完整的资料与分析同步。商业分析的月度复核也未单独配置定时任务。

`npm run companies:sync` 同一周完成后会跳过重复成功检查；失败可重试，手工复核可加 `--force`。`npm run companies:check` 只检查数据与引用，不联网。自动检查页面变动只是线索；核实后将候选的 `status` 改为 `reviewed`，或确认为无实质变化后改为 `dismissed`。不能把变动哈希写成产品发布。

对每个实际核实的字段更新日期，保留直接来源和事件日期；不统一刷全体公司日期。`reviewedAt` 表示该公司全部档案资料已复核，`analysisAt` 表示商业分析已复核；成功下载一个页面只更新 `monitor.json` 的来源检查日期。仅完成部分字段时不更新公司整体日期。纯 JavaScript 页面通过浏览器检查，当前 Instinct 产品主页属于此类。

`verified` 是实际检查或独立证据支持的事实；`disclosed` 是公司或投资方披露；`analysis` 是有依据的判断；`unknown` 保留资料缺口。事实必须引用该公司的来源 ID。融资额、估值、累计融资、ARR 与员工股权交易分别记录；不能把历史融资写成最新融资。

收录范围限定为能接受用户委派并交付实际任务结果的个人助理与行业 Agent；排除开发平台、框架、API 和纯生成、搜索或写作工具。新增公司需用户确认；归档公司不自动重新纳入。

每次周同步核查当前收录公司的产品、价格、团队与资本消息。优先查看新发布的一手页面；公司列表只用于发现线索。付费数据 API 暂未接入，使用商业数据库前单独确认预算与公开展示许可。

原工作区有其他未提交改动时，在独立工作树中更新，从当前远程 main 开始，不复制、提交或覆盖用户改动。只提交本模块和必要字体变化。发布前执行 `node --test tests/company-observer.test.mjs`、`npm run companies:check`、`npm run fonts:update`、`npm run build`，检查公司目录搜索、分类、地区、空结果、手机布局及动态与来源链接，再推送并验证 Vercel 线上页面。来源失败或完整性检查失败不能宣称本周已完整同步。
