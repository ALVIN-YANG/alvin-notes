实际工作中要用到的 IPv4 知识就三块：私网三段地址（`10/8`、`172.16/12`、`192.168/16`）只在内部路由，几个特殊地址（回环、链路本地、广播）各自有固定含义，子网划分今天一律用 CIDR 前缀表示。教科书里的 A~E 五类地址是 CIDR 出现之前的历史分类，只用来读懂旧资料，放在文末。

## 私网地址与公网地址

公网 IP 全球唯一，可以在互联网上直接路由。为了节省公网地址，[RFC 1918](https://www.rfc-editor.org/rfc/rfc1918.html) 规定了三段仅限内部网络使用的私网地址，它们不会出现在互联网路由表中：

| 地址范围 | CIDR | 可用地址数 | 常见场景 |
| --- | --- | --- | --- |
| 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 | 约 1677 万 | 企业内网、云 VPC |
| 172.16.0.0 ~ 172.31.255.255 | 172.16.0.0/12 | 约 104 万 | Docker 默认网络、中型企业 |
| 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 | 约 6.5 万 | 家庭路由器、小型办公网 |

私网设备通过 NAT（网络地址转换）访问互联网：路由器把私网地址转换成自己的公网地址发出去，收到响应后再转回来。

```
你的电脑             路由器                  互联网
192.168.1.100  →  NAT 转换  →  203.0.113.5  →  目标服务器
               ←  NAT 还原  ←                ←  响应
```

## 特殊地址速查

这些范围在 [IANA IPv4 特殊用途地址注册表](https://www.iana.org/assignments/iana-ipv4-special-registry/)中都有登记：

| 范围 | 名称 | 含义与用法 | 来源 |
| --- | --- | --- | --- |
| 127.0.0.0/8 | 回环地址 | 数据不离开本机网卡，用于本地服务测试；实际几乎只用 `127.0.0.1`（localhost） | RFC 1122 |
| 169.254.0.0/16 | 链路本地地址 | DHCP 分配失败时操作系统自动分配；看到设备拿到 `169.254.x.x` 说明网络连接有问题；只在同一链路内可通信 | RFC 3927 |
| 0.0.0.0 | 未指定地址 | 含义取决于上下文（见下表） | RFC 1122 |
| 255.255.255.255 | 受限广播地址 | 向同一子网内所有设备发送；DHCP 客户端获取 IP 前用广播寻找服务器 | RFC 919 |

`0.0.0.0` 的三种常见含义：

| 场景 | 含义 |
| --- | --- |
| 服务监听 `0.0.0.0:8080` | 监听本机所有网卡的所有 IP |
| 路由表中 `0.0.0.0/0` | 默认路由，匹配所有目标地址 |
| DHCP 请求源地址 | 表示「我还没有 IP 地址」 |

## CIDR 与子网划分

一个 IPv4 地址是 32 位二进制，通常写成点分十进制（如 `192.168.1.1`），分为网络位和主机位两部分。子网掩码决定哪几位是网络位，CIDR 写法直接用前缀长度表示：

```
传统：192.168.1.0  子网掩码 255.255.255.0
CIDR：192.168.1.0/24        ← /24 表示前 24 位是网络位
```

常用前缀速查：

| CIDR | 子网掩码 | 可用主机数 | 常见用途 |
| --- | --- | --- | --- |
| /8 | 255.0.0.0 | 16,777,214 | 大型内网整体规划 |
| /16 | 255.255.0.0 | 65,534 | VPC、集群网段 |
| /24 | 255.255.255.0 | 254 | 单个子网，最常用 |
| /32 | 255.255.255.255 | 1 | 单台主机，安全组规则常见 |

可用主机数 = 2^(32 − 前缀长度) − 2，减去的 2 个地址是网络地址（全 0）和广播地址（全 1）。例如 /24：2^8 − 2 = 254 台主机。

## 实际工作中的场景

云服务器 VPC：

```
VPC 网段：       10.0.0.0/16     ← 私网 A 段
子网 1（Web）：   10.0.1.0/24    ← 254 台 Web 服务器
子网 2（DB）：    10.0.2.0/24    ← 254 台数据库
弹性公网 IP：     47.98.x.x      ← 云厂商分配的公网地址
```

Docker 默认网络：

```
默认 bridge：   172.17.0.0/16    ← 容器默认网段（私网 B 段）
容器 IP 示例：  172.17.0.2
宿主机访问：    127.0.0.1:8080   ← 回环地址 + 端口映射
```

K8s 集群（网段可配置，以下是常见取值）：

```
Node 网络：     10.0.0.0/16      ← 节点 IP
Pod 网络：      172.20.0.0/16    ← Pod IP（私网 B 段）
Service 网络：  10.96.0.0/12     ← ClusterIP
```

## 附：A~E 五类地址（历史分类）

IPv4 早年按首字节的二进制前缀把地址分为 A~E 五类，称为分类编址（classful addressing）。它在 1993 年已被 CIDR（无类别域间路由，[RFC 4632](https://www.rfc-editor.org/rfc/rfc4632.html)）取代：今天的地址分配和路由都按任意长度的前缀进行，不再按类划界。这张表的价值是帮你读懂旧文档、理解“默认掩码”说法的来历，不要拿它当现行分配规则。

| 类别 | 首字节范围 | 当时的默认掩码 | 网络数 | 每网络主机数 | 当时的定位 |
| --- | --- | --- | --- | --- | --- |
| A 类 | 1 ~ 126 | 255.0.0.0 (/8) | 126 | 约 1677 万 | 超大型网络 |
| B 类 | 128 ~ 191 | 255.255.0.0 (/16) | 约 1.6 万 | 约 6.5 万 | 中型网络 |
| C 类 | 192 ~ 223 | 255.255.255.0 (/24) | 约 209 万 | 254 | 小型网络 |
| D 类 | 224 ~ 239 | — | — | — | 组播（至今仍在使用） |
| E 类 | 240 ~ 255 | — | — | — | 保留/实验 |
