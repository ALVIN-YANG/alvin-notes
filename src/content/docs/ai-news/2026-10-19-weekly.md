## 本期主线

这一周最实在的变化来自供应链安全。OpenClaw 在 v2026.10.6 中把 Node 运行时要求提高到 24.22.1+ 或 26.12.1+，理由是旧版本会接受由被入侵证书签发的 TLS 链。同一时期 OpenCode 把内置 Bun 升到 1.4.4，带上 Brotli、TLS、HTTP/1.1 到 HTTP/3、WebSocket 的安全修复。两个项目都在做同一件事，把运行时本身当成需要打补丁的依赖来管理，而不是只盯着业务代码。

Agent 的权限边界也在被重新划线。1Password 推出让 Agent 代登录但不接触密码的能力，同期美国多家大行开始封锁用客户凭据登录的 Agent，多数只准备开放只读权限。工具侧在放开，账户侧在收紧，中间那层授权协议会成为实际落地的瓶颈。

工程侧则出现了对成本的直接核算。Cloudflare 通过 prompt caching 和模型路由把 AI 代码审查的单次成本降了 68%，哈佛基于 Jellyfish 数据对 718 家企业的研究指出 AI 生成的代码量上升没有带来等量的完成工作量，瓶颈被推到下游环节。这两条放在一起看，说明优化点已经从“生成更快”转向“链路更省”。

## 01 运行时与依赖的安全补丁

### [OpenClaw v2026.10.6 强制要求打过补丁的 Node 运行时](https://github.com/openclaw/openclaw/releases/tag/v2026.10.6)

`一手` · `GitHub Release` · `10 月 24 日`

该版本要求 Node 24 线使用 24.22.1 及以上，26 线使用 26.12.1 及以上，原因是这些版本会拒绝由被入侵证书签发的 TLS 链。升级前需要先确认部署环境的 Node 版本，容器镜像和 CI 基础镜像都要同步改，否则启动阶段就会失败。

### [OpenCode v1.19.4 升级内置 Bun 到 1.4.4](https://github.com/anomalyco/opencode/releases/tag/v1.19.4)

`一手` · `GitHub Release` · `10 月 24 日`

Release 说明把 Bun 1.4.4 的安全修复列为改进项，覆盖 Brotli、TLS、HTTP/1.1、HTTP/2、HTTP/3 和 WebSocket。对把 OpenCode 嵌进自有工具链的团队，这意味着网络栈层面的行为可能变化，升级后值得跑一遍长连接和压缩相关的回归。

### [OpenClaw v2026.10.10-beta.2 在改文件前拒绝不完整的 apply_patch](https://github.com/openclaw/openclaw/releases/tag/v2026.10.10-beta.2)

`一手` · `GitHub Release` · `10 月 21 日`

修复项写明，当多文件 `apply_patch` 中后续某个更新目标缺失或上下文不匹配时，会在改动任何文件之前整体拒绝。这解决的是部分写入导致的半成品工作区，对让 Agent 批量改仓库的流程是必要的前置校验。

## 02 Agent 的账户权限正在被两头拉扯

### [1Password 让 Agent 代登录而不接触密码](https://techcrunch.com/2026/10/22/1password-launches-a-way-for-ai-agents-to-log-in-on-your-behalf-without-seeing-your-password/)

`资讯` · `TechCrunch AI` · `10 月 24 日`

据报道，该功能允许 Agent 登录客户的个人账户，同时不暴露用于保护账户的私有凭据。落地时要确认的是授权范围如何限定、会话如何回收，以及 Agent 被劫持时凭据是否仍然不可导出。

### [美国多家大行封锁用客户凭据登录的 AI Agent](https://the-decoder.com/major-us-banks-are-locking-out-ai-agents-that-log-in-with-customer-credentials/)

`资讯` · `The Decoder` · `10 月 24 日`

报道称客户让 Agent 使用自己的凭据访问 Morgan Stanley、JPMorgan 等机构的账户，有时并无明确指令。Morgan Stanley 已封禁 Agent，其他银行在限制访问，多数计划只开放只读。做金融类 Agent 的团队需要按只读、可审计、可撤销来设计接入方式，而不是复用用户密码。

### [Anthropic 将 Agent Skills 标准捐给 Linux 基金会下的 AAIF](https://simonwillison.net/2026/Oct/22/donating-agent-skills/)

`开发者` · `Simon Willison` · `10 月 23 日`

Anthropic 宣布把 Agent Skills 标准捐给 Agentic AI Foundation，该基金会由 Anthropic 与 Block、OpenAI 共同创立，目标是保持标准开放、社区驱动、厂商中立。对已经在写 Skills 的团队，短期动作是关注标准仓库的迁移地址和版本约定，避免绑定单一实现的私有格式。

## 03 推理成本的优化落到具体数字

### [Cloudflare 用 prompt caching 和模型路由把推理账单降了 68%](https://blog.cloudflare.com/obsessive-inference-optimization/)

`一手` · `Cloudflare Blog` · `10 月 21 日`

起因是 AI 代码审查的单次运行成本翻倍，团队从 token 用量入手，最终把推理账单削减 68%，同时审查速度提升。可复用的做法是先按调用类型拆 token 消耗，再决定哪些请求走缓存、哪些降级到更小的模型，而不是整体换模型。

### [哈佛基于 718 家企业的研究称 AI 代码量上升未带来等量产出](https://www.infoq.com/news/2026/10/jellyfish-ai-productivity/)

`资讯` · `InfoQ AI/ML` · `10 月 25 日`

研究使用 Jellyfish 分析平台的数据，发现 AI 编程助手和 Agent 提高了代码量，但没有转化为完成工作量的同比例增长，部分原因是生成代码加重了后续环节的负担。评估 AI 编码投入时，把评审、测试和返工计入同一张成本表，比只看生成速度更接近真实收益。

### [OpenAI 推出 Decisions API](https://openai.com/index/decisions-api)

`一手` · `OpenAI 官方` · `10 月 25 日`

官方描述为面向应用提供快速、聚焦、低成本的决定能力。适合把分类、路由、判定这类高频小请求从通用对话模型里拆出来单独计价，接入前需要用自己的请求分布测一遍准确率和单次成本。

## 04 数据与 Agent 基础设施的版本节点

### [Databricks 多语句事务正式可用](https://www.databricks.com/blog/transactions-are-generally-available-advancing-warehousing-lakehouse)

`一手` · `Databricks Blog` · `10 月 19 日`

Multi-Statement Transactions 进入 GA，组织可以在 Lakehouse 上运行需要跨语句原子性的仓库型负载。迁移现有 ETL 时要确认隔离级别和并发写入下的行为，尤其是多个 Agent 同时写同一张表的场景。

### [Databricks 在 Agent Bricks 上推出 Agent Memory](https://www.databricks.com/blog/introducing-agent-memory-databricks)

`一手` · `Databricks Blog` · `10 月 21 日`

官方同时发布了一篇讲生产级 Agent 持久记忆设计的文章。对自建记忆层的团队，值得对照的是它如何划分记忆的写入、检索与过期，以及这些环节是否落在同一套权限模型下。

### [LangChain 1.4.7 与 langchain-core 1.7.0 发布](https://github.com/langchain-ai/langchain/releases/tag/langchain%3D%3D1.4.7)

`一手` · `GitHub Release` · `10 月 22 日`

core 1.7.0 的新特性是为流式工具调用参数发出 `tool-call-delta`。做流式 UI 或需要在参数生成过程中提前校验的调用方，可以据此增量渲染和拦截，而不必等整个参数对象拼完。
