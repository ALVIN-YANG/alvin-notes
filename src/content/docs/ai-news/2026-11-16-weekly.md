## 本期主线

这一周最清楚的变化是模型发布之后，配套工程层立刻跟着动。OpenAI 在 11 月 17 日推出 GPT-6.2 Astra 和 Sol，API 名为 `gpt-6.2-astra` 和 `gpt-6.2-sol`，官方称在专业输出、编码、计算机使用和成本效率上都有改进。随后几天，LangChain 的 `langchain-openai` 连发 1.8.1 和 1.8.3，后者专门修复 Codex 在 GPT-6.2 上的 prompt caching；OpenCode v2.3.2 也处理了 GPT-6.2 不缓存 Responses `instructions` 字段导致每步重复计费的问题。模型换代不只是换个名字，缓存路径和请求字段的细节直接决定账单。

另一条线是 Agent 的执行边界在被重新划定。Cloudflare 把面向 AI Agent 的实验浏览器引擎 Kitesurf 开源，可以本地运行或部署到 Workers；Simon Willison 同期写了外部沙箱方案，目标是在跑本地模型时避免提示注入造成机器上的破坏性操作。Uber 则公开了覆盖 Agent 全生命周期的安全框架，指出传统身份和 API 控制无法约束会动态推理外部内容并执行真实动作的 Agent。三件事指向同一个工程问题，Agent 能做什么、在哪做、由谁批准，正在从提示词层面下沉到运行时和基础设施层面。

材料里也有需要打折的部分。Nvidia 高层变动、孙正义洽购 SK 海力士等消息多为媒体转述，且带有 reportedly 一类表述，不影响本周的开发决策。Databricks 和 OpenAI 的大量博客偏案例与方法论，只有少数带明确版本或限制条件的内容被收入下文。

## 01 模型换代后的适配成本

### [OpenAI 发布 GPT-6.2 Astra 和 Sol](https://openai.com/index/introducing-gpt-6-2-astra-sol)

`一手` · `OpenAI 官方` · `11 月 17 日`

OpenAI 推出两个模型，Astra 定位处理最难的项目，Sol 定位日常工作的效率与通用性，API 标识分别为 `gpt-6.2-astra` 和 `gpt-6.2-sol`，覆盖 ChatGPT Work、Codex 和 API。官方描述的能力方向是专业输出、编码、计算机使用和更低的单位成本。

对已经在跑 Agent 流水线的团队，这意味着要重新核对两件事，一是模型标识切换后各框架的默认参数是否仍然成立，二是计费结构变化是否被正确反映到成本估算里。下面两条框架修复说明，第二件事并不自动发生。

### [langchain-openai 1.8.3 修复 GPT-6.2 的 Codex 缓存](https://github.com/langchain-ai/langchain/releases/tag/langchain-openai%3D%3D1.8.3)

`一手` · `LangChain Release` · `11 月 19 日`

1.8.3 的主要变更是 `fix(openai): enable Codex prompt caching on GPT-6.2`。此前的 1.8.1 已经修过从 done 事件恢复函数调用参数的问题。两个版本间隔很短，说明新模型接入后请求与响应路径上出现了需要连续修补的细节。

使用 LangChain 调用 Codex 相关接口的项目应至少升到 1.8.3，否则缓存不生效会直接体现为输入 token 计费上升。升级后值得对比同一任务在升级前后的账单，确认缓存命中确实发生。

### [OpenCode v2.3.2 处理 GPT-6.2 系统提示不缓存问题](https://github.com/anomalyco/opencode/releases/tag/v2.3.2)

`一手` · `OpenCode Release` · `11 月 19 日`

Release 说明指出，GPT-6.2 模型不会缓存通过 Responses `instructions` 字段发送的系统提示，导致每一步都按未缓存输入重新计费。OpenCode 改为不再把系统提示放在该字段发送。

这是一个典型的模型行为差异引发的成本问题。自建 Agent 循环的团队如果直接把系统提示塞进 `instructions`，在多步任务里会持续多付钱。验证方法是抓一次请求日志，确认系统提示实际落在哪个字段，再对照账单看缓存 token 数是否非零。

## 02 Agent 的沙箱与权限边界

### [Cloudflare 开源 Agent 浏览器引擎 Kitesurf](https://blog.cloudflare.com/kitesurf-open-source/)

`一手` · `Cloudflare Blog` · `11 月 13 日`

Kitesurf 是 Cloudflare 为 AI Agent 做的实验性浏览器引擎，现在以开源形式放出，可以查看代码、本地运行，或部署自己的实例到 Cloudflare Workers。

对需要让 Agent 访问网页的团队，这提供了一个可审计的执行层替代方案。部署到 Workers 意味着浏览器行为跑在隔离环境里，而不是开发机上。值得验证的是本地运行与 Workers 部署两种模式下，Agent 能触达的网络范围和凭据隔离是否一致。

### [面向编码 Agent 的外部沙箱实践](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/)

`开发者` · `Simon Willison` · `11 月 17 日`

作者记录了探索外部沙箱的过程，重点是在试用本地模型时降低风险，避免模型出错或遭遇提示注入后在本机执行破坏性操作。

这类实践的价值在于把安全假设写清楚。如果 Agent 运行在外部沙箱，那么文件系统、网络和环境变量的可见范围就是可定义的边界。团队可以据此检查现有 Agent 是否仍在宿主环境直接执行代码。

### [Uber 的 Agent 全生命周期安全框架](https://www.infoq.com/news/2026/11/uber-secure-ai-framework/)

`资讯` · `InfoQ AI/ML` · `11 月 15 日`

InfoQ 报道 Uber Engineering 的文章，指出传统身份与 API 控制无法保护会对外部内容做动态推理并执行真实动作的 Agent，Uber 因此建立了判断某次 Agent 动作在给定用户上下文下是否合适的框架。

这给企业内落地 Agent 提供了一个检查清单的方向，权限判断不能只看调用者是谁，还要看这次动作的内容和上下文。正在做内部 Agent 平台的团队可以对照自己的审批链路，确认是否存在只校验身份、不校验动作的情况。

## 03 工具链版本与运行时

### [vLLM v0.34.0 发布](https://github.com/vllm-project/vllm/releases/tag/v0.34.0)

`一手` · `vLLM Release` · `11 月 18 日`

该版本包含来自 412 位贡献者的 1,061 个提交，其中 120 位是新贡献者。Release 说明以提交规模为主，未在摘要中列出具体行为变更。

对自建推理服务的团队，这个体量的版本通常意味着需要重新跑一遍基准和回归。升级前应确认所用模型和量化配置在 0.34.0 下的兼容性，并对比吞吐与显存占用。

### [PostgreSQL 19 正式发布](https://simonwillison.net/2026/Nov/19/postgresql-19/)

`开发者` · `Simon Willison` · `11 月 19 日`

PostgreSQL 19 已 GA。作者提到今年发布比往年 9 月的惯例晚了约两个月，主要原因是团队需要处理一批由 AI 报告引发的漏洞问题。

对把 Postgres 作为 Agent 状态存储或向量检索后端的项目，这是一次需要排期的升级。作者同时提到 Homebrew 已带 SQLite 3.54.1，该版本的一个修复曾破坏 LLM 的日志代码，说明底层依赖升级会连带影响上层工具，升级窗口应把周边工具一起验证。

### [llm 0.37.3 修复 Homebrew SQLite 兼容问题](https://simonwillison.net/2026/Nov/16/llm/)

`开发者` · `Simon Willison` · `11 月 16 日`

这是一个 bug fix 版本，主要解决 Homebrew 最新 SQLite 3.54.1 导致 LLM 日志代码失效的问题。作者说明问题源自 SQLite 3.54.0 起对 `json_object` 相关 SQL 的行为变化。

用 Homebrew 安装 LLM 的用户应升级到 0.37.3。这也提醒依赖系统级 SQLite 的 Python 工具，在系统包更新后可能出现非预期失败，排查时应先确认 SQLite 版本。

## 04 开源模型与开放权重

### [腾讯混元开源 Hy4 flash](https://www.ithome.com/1/028/701.htm)

`资讯` · `IT之家` · `11 月 18 日`

混元开源 Hy4 flash、Hy4 flash-FP8 和 Hy4 flash Base，可在 GitHub、Hugging Face、ModelScope 和 GitCode 获取。总参数量 224B，其中含 64B Engram 参数，每 token 激活 12B，支持多模态输入和 100 万 token 上下文，官方称 API 价格较 Hy4 大幅降低。

激活参数远小于总参数，意味着推理成本更接近 12B 级别模型，适合在有限显存下部署长上下文任务。团队在选型时应实测 100 万上下文下的实际显存占用和延迟，而不是只看参数量。

### [Cloudflare 将 Clairic 与 Clairic-flash 转为开放权重](https://blog.cloudflare.com/open-clairic/)

`一手` · `Cloudflare Blog` · `11 月 18 日`

Clairic 从预览转为正式，Clairic-flash 加入 Workers AI，两者都是抽取类模型并以开放权重发布，来自新的 Workers AI Superintelligence 团队。

抽取类模型开放权重，对需要结构化信息提取的流水线有直接价值，可以在 Workers AI 上直接调用，也可以自行部署。值得验证的是两个模型在长文档和边界格式上的抽取准确率差异。

### [Hugging Face 与 OpenRouter 合作简化开放权重模型运行](https://huggingface.co/blog/openrouter)

`一手` · `Hugging Face Blog` · `11 月 16 日`

双方宣布合作，目标是让开放权重模型更容易运行。原始来源未提供摘要，具体接入方式和计费细节需查看原文。

如果合作落地为统一的模型调用入口，团队在评估开放权重模型时可以少做一层部署工作。下周可观察是否出现具体的 API 文档或模型列表变更。
