HTTPS 是通过 TLS 保护的 HTTP。TLS 为传输提供机密性、完整性与端点认证；常见浏览器场景通过证书链和主机名校验确认服务器身份，再协商会话密钥保护应用数据。TLS 不会自动让业务接口具备用户权限检查。

<InterviewVisual src="/images/interview/cards/agent-https-tls.webp" alt="HTTP 和 HTTPS 有什么区别？TLS 怎样防窃听与冒充？图解。校验证书与主机名；协商密钥，保护应用数据；HTTPS ≠ 业务授权；HTTP/3 使用 QUIC。" />

以 TLS 1.3 的常见握手为例，客户端与服务端协商参数并交换密钥材料，服务端用证书与签名证明身份，之后使用对称密码保护流量。证书通常不是拿来直接加密整份请求；私钥也不应传给客户端。

HTTP/1.1、HTTP/2 常在 TCP 上使用 TLS；HTTP/3 则使用结合 TLS 1.3 的 QUIC。不能一概说所有 HTTPS 都先建立 TCP。调用模型接口出现证书错误时，应检查证书链、域名、时间和代理，不应直接关闭验证。
