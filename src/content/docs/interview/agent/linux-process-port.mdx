先确认目标机器、容器或网络命名空间，再用 ps、top 等查看进程与资源，用 ss -lntp 查看 TCP 监听和关联进程。部分进程信息需要相应权限；查不到不一定代表程序没有运行，也可能看错了命名空间。

<InterviewVisual src="/images/interview/cards/agent-linux-process-port.webp" alt="Linux 上怎样查进程、端口和资源占用？查到监听就代表服务正常吗？图解。先确认机器与命名空间；进程：ps / top；监听：ss -lntp；监听成功 ≠ 业务正常。" />

找到 PID 后，再查进程状态、CPU、内存、线程、打开文件和启动参数，结合日志与具体请求验证。僵尸进程是子进程已退出、父进程尚未回收退出状态；它不再执行任务，直接反复 kill 子进程解决不了父进程未回收的问题。

端口监听只证明有套接字接收连接，不证明路由、TLS、认证、依赖和业务请求都正常。用一次与故障场景对应的请求确认服务行为，并区分连接失败、响应错误和业务失败。
