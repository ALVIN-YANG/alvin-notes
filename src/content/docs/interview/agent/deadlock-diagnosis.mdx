死锁是参与者相互等待对方持有的资源，谁都无法继续。例如，线程 A 拿着锁 1 等锁 2，线程 B 拿着锁 2 等锁 1。

经典资源死锁需要互斥、持有并等待、不可抢占、循环等待四个条件同时成立。工程上常通过统一获取资源的顺序、减少嵌套持锁来破坏这些条件。比如，多个账户转账始终按账户 ID 顺序加锁，就能避免这类相反顺序造成的锁环；还要检查代码是否持锁等待网络或其他任务。

服务卡住时，先取得线程栈，核对每个线程持有什么、等待什么，再找到形成环的调用位置。Java 的 `ThreadMXBean.findDeadlockedThreads()` 能检查对象监视器和可拥有同步器的部分死锁，不能据此排除数据库锁、跨进程等待等所有问题。

超时只有在等待方能退出、释放已持有资源，并处理半完成操作时才有帮助。超时后仍拿着旧锁重试，可能继续阻塞；双方不断同时退让又重试，也可能形成活锁。不能把“配置了超时”当成死锁已经解决。
