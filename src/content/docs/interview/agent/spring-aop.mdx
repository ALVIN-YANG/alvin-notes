Spring AOP 通过代理，在目标方法调用前后加入事务、计时等公共逻辑。调用方先进入代理，代理执行匹配的增强逻辑，再调用业务对象；这样不必在每个业务方法里重复写这些代码。

Spring AOP 支持 JDK 接口代理和 CGLIB 子类代理，实际选择还受配置和 Spring Boot 默认设置影响。子类代理不能重写 `final` 或 `private` 方法，因此不能用这种方式增强它们。

自调用的关键是调用有没有经过代理。例如，外部调用未开启事务的 `submit()`，它内部用 `this.save()` 调用带有 `@Transactional` 的方法。在默认代理模式下，这次内部调用绕过代理，`save()` 上的事务声明不会因此生效。如果外层本来就在事务中，内部代码仍可能在该事务里执行，不能笼统说成“自调用就没有事务”。

常见处理是把事务操作移到独立 Bean，由调用方通过容器提供的代理调用；也可以按需要使用编程式事务。AspectJ 织入与代理模式不同，不能套用同一条自调用结论。
