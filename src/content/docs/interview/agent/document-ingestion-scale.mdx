大规模入库应把上传、解析、切片、Embedding 和索引发布拆成可恢复的阶段。上传先返回任务标识，后台按资源限额处理；用户看到明确进度，不能把上传成功显示为可检索。

```mermaid
flowchart TB
  A["接收上传任务"] --> B["限流解析图文"]
  B["限流解析图文"] --> C["批量生成向量"]
  C["批量生成向量"] --> D["验证并发布索引"]
```

## 每个阶段都能查状态和重试

任务保存文档版本、解析器版本和内容哈希。OCR 与图像模型限制并发，Embedding 批量执行并处理限流，索引阶段验证切片数量。只有全部必要阶段成功才发布版本；坏页允许隔离，但需标明覆盖缺口。

### 同一文档重复上传会不会重复收费和建索引？

按租户、内容哈希和处理版本识别重复任务，用唯一约束或原子创建阻止两个 Worker 同时开工。重试复用阶段操作标识，索引写入采用稳定的文档与切片 ID；处理器版本变化时允许重建。

本地任务去重不等于外部调用只计费一次。OCR 或 Embedding 请求超时后可能已经完成；下游支持幂等键或状态查询时复用同一操作标识核对，否则记录结果未知，按明确的补偿或人工处理策略恢复，不能直接承诺重复上传绝不重复计费。
