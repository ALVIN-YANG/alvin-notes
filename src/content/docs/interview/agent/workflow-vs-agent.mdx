Workflow 按写好的步骤执行，Agent 由模型根据当前结果决定下一步。两者都能调用 LLM，也都能调用工具；区别在于执行顺序由谁决定。

售后流程如果已经明确为“查订单 → 检查规则 → 给出方案”，用 Workflow 就够了。模型可以理解用户的说法，但订单归属、退款金额和是否可退，要交给业务代码判断。

<InterviewVisual src="/images/interview/cards/agent-workflow-vs-agent.webp" alt="Workflow 与 Agent图解。Workflow：预定控制流；Agent：按观察选下一步；稳定步骤用确定性流程；不确定部分受控决策；两者可以组合。" />

如果任务是“调查这笔订单为什么异常”，下一步要查物流、支付还是库存，得看前一步找到什么。这类任务更适合 Agent。工具权限、超时、调用次数和结束条件仍由应用控制。

### Function calling 就是 Agent 吗？

不是。程序固定调用一次工具，也属于 Workflow。模型能在循环中根据工具结果选择下一步，才符合这里采用的 Agent 定义。不同团队对这个词的用法不完全一致。

### 怎样判断 Agent 值不值得用？

让固定流程和 Agent 做同一批任务，比较完成率、错误操作、人工接管、耗时和成本。如果效果差不多，保留固定流程。只有任务确实需要动态探索时，再增加自主性。
