## 一条工单任务怎么测

任务是“查询 T42，写解决建议，未经确认不要发给客户”。检查四件事：建议是否符合工单事实；操作的是不是 T42；有没有调用发送工具、有没有真实授权；有没有超时或无效重试。

没有要求固定工具顺序，就别因为另一条合法路径而判失败。测试集应包括常见任务、历史故障和边界情况。改动后重跑已通过的任务，防止修好一处又破坏另一处。

比较两版 Agent 时，固定初始数据、工具行为和成功条件，记录模型及提示词版本。涉及写操作，用隔离环境恢复同一初始状态，避免前一次执行改变下一次的题目。重要权限违规应单独判定，不能用回答质量高分抵消。

### pass@k 和 pass^k 有什么区别？

pass@k 看 k 次里至少成功一次；pass^k 看 k 次是否全部成功。允许生成多个候选再验证的任务，可以关注前者；每次都要可靠完成的任务，更关心后者。

假设每次成功率都是 80%，且尝试独立，三次至少成功一次是 99.2%，三次全成功只有 51.2%。实际任务难度和尝试相关性会影响结果。

### 有 Trace 就算有评测了吗？

不算。Trace 记录发生了什么，评测规则判断做得对不对。只有日志，无法判成功；只有总分，难以查原因。
