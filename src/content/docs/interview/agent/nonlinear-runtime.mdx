输入增至十倍、耗时增至百倍，值得怀疑重复扫描等 O(n²) 操作，但两个测量点不能证明算法复杂度。也可能是数据变大后触发频繁 GC、磁盘换页、数据库执行计划变化，或下游排队。

先保证比较条件一致：输入分布、代码和配置、并发量、预热与缓存状态相同。再测几个中间规模，并把总耗时拆成计算、数据库、网络和等待，观察哪个部分增长最快。

如果 CPU 忙，看剖析结果是否有嵌套遍历或重复序列化；如果主要在等待，查锁、连接池、磁盘和下游请求；如果内存明显增长，查分配量、GC、缺页与工作集是否超过可用内存。

例如，循环中对列表做 `contains`，可能累计扫描 O(n²) 次；换成哈希集合后，再用相同输入检查耗时和结果。如果瓶颈实际是数据库每条一次往返，换容器未必有效，应核对是否需要批量访问。每次修改都验证对应的瓶颈是否下降。
